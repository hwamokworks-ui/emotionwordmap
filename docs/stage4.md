**바이브코딩 기반 디지털플랫폼 제작**

**4단계. 기능 우선순위(MoSCoW) & 사이트맵**

# **① 기능 브레인스토밍 & MoSCoW 분류**

3단계에서 만든 페르소나·저니맵·컨셉 스테이트먼트를 근거로, 서비스에 필요한 기능 후보를 최대한 많이 떠올린 뒤 Must/Should/Could/Won't로 분류합니다.

**프롬프트 예시**

| 1\~3단계에서 작성한 워크시트 파일(문제정의·근본원인, 페르소나, 저니맵, 컨셉 스테이트먼트가 담긴 파일)을 첨부해줘. 이 내용을 참고해서, 서비스에 필요한 핵심 기능 후보들을 Must / Should / Could / Won't로 분류해줘. 각 기능이 왜 그 등급인지 이유를 페르소나의 목표·페인포인트와 연결해서 설명해줘. Won't로 분류한 기능은 지금 단계에서 제외하는 이유도 한 줄씩 적어줘. UI 디자인은 전혀 고려하지 않아도 돼. |
| :---- |

*💡 Won't로 분류하는 것도 근거가 있어야 합니다 — '왜 지금은 안 하는지'까지 적어보세요.*

| 기능 후보 | 등급 (Must/Should/Could/Won't) | 근거 (페르소나 목표·페인포인트 연결) |
| :---- | :---- | :---- |
| 감정 입력 | Must | 감정이나 느낌을 직접 입력해 탐색을 시작하는 기본 진입 기능. 자신의 감정을 정확하게 이해하고 싶다는 목표와 연결된다. |
| 감정 검색 | Must | 이미 알고 있는 감정 단어에서 탐색을 시작할 수 있도록 한다. |
| 상황으로 감정 찾기 | Must | 감정 단어 자체가 떠오르지 않는 사용자가 자신의 경험과 상황에서 출발할 수 있게 한다. “여러 감정이 섞이면 어떤 단어로 표현해야 할지 모호하다”는 핵심 페인포인트를 직접 해결한다. |
| 감정 단어 예시·추천 | Must | 첫 화면에서 무엇을 입력해야 할지 막막한 사용자를 위해 가까운 감정 단어의 예시를 제공한다. 감정 어휘가 부족한 사용자의 진입 장벽을 낮춘다. |
| 감정 어휘 지도 | Must | 서비스의 핵심 차별 기능. 감정의 위치와 주변 관계를 탐색하면서 자신에게 가까운 감정을 발견하게 한다. |
| 감정 영역 탐색 | Must | 특정 감정 주변의 감정 어휘를 넓게 탐색할 수 있게 한다. 감정 어휘를 확장하고 자연스럽게 발견한다는 HMW 1·3과 연결된다. |
| 유사·관련·반대 감정 탐색 | Must | 비슷하지만 다른 감정을 비교하며 자신의 감정에 가까운 후보를 좁혀가는 핵심 탐색 과정이다. |
| 감정 간 거리·관계 확인 | Must | 감정의 미묘한 차이를 이해하고 자신에게 더 가까운 감정을 발견하도록 한다. 감정 지도 서비스의 핵심 경험이다. |
| 감정 비교·제외 | Must | “비슷하지만 이건 아닌 것 같다”는 방식으로 후보를 직접 비교하고 제외할 수 있게 한다. 감정을 하나의 답으로 강제하지 않고 스스로 발견하게 한다. |
| 감정 상세 정보 | Must | 최종 후보의 의미와 특징을 확인해 실제 자신이 느낀 감정인지 판단할 수 있게 한다. |
| 감정이 나타나는 상황 | Must | 감정의 사전적 의미뿐 아니라 실제 상황을 함께 보여줘 자신의 경험과 감정을 연결하도록 한다. 근본원인의 “감정 어휘와 자신의 경험을 연결해 탐색할 기회 부족”을 직접 해결한다. |
| 감정 기록 | Must | 발견한 감정과 자신의 경험을 연결해 기록한다. 감정 탐색을 일회성 경험으로 끝내지 않게 한다. |
| 개인 기록 관리 | Must | 실제 인터뷰에서 “일기도 결국 누군가 볼 수 있기 때문에 솔직하게 쓰기 어렵다”는 의견이 확인됨. 개인적인 감정을 안전하게 기록하고 관리할 수 있는 환경이 필요하다. |
| 기록 히스토리 | Must | 과거의 감정과 상황을 다시 확인해 자신의 감정을 돌아볼 수 있게 한다. |
| 감정 표현 문장 추천 | Should | 찾은 감정을 실제 사람에게 전달할 수 있는 표현으로 연결한다. HMW 2의 “적절한 감정 단어를 찾고 전달”하는 목표를 지원하지만 핵심 탐색 이후 단계다. |
| 표현 대상·상황 선택 | Should | 같은 감정도 상대와 상황에 따라 표현 방식이 달라질 수 있으므로 실제 전달 상황에 맞는 표현을 돕는다. |
| 이모티콘 추천 | Should | 발견한 감정을 메신저 등에서 쉽게 표현하도록 돕는다. 기존 아이디어인 ‘감정 어휘 확장 및 이모티콘 추천’의 표현 확장 기능이다. |
| 감정 도감 | Should | 탐색하면서 발견한 감정 어휘를 축적해 감정 어휘 확장이라는 목표를 지속적으로 지원한다. |
| 감정 어휘 수집 | Should | 새롭게 발견한 감정을 모으고 자신의 감정 어휘를 확장하는 경험을 제공한다. |
| 감정 리포트 | Should | 기록이 쌓인 후 자주 느끼는 감정과 변화·패턴을 확인해 자기이해를 확장한다. |
| 뱃지·업적 | Should | 새로운 감정이나 영역을 발견하는 과정을 성취감과 연결해 반복 탐색을 유도한다. |
| 감정 영역 발견 보상 | Could | 새로운 영역을 발견했을 때 추가적인 재미를 제공할 수 있지만, 핵심 탐색 기능보다 우선순위가 낮다. |
| 캐릭터 성장·꾸미기 | Could | 감정 탐색과 기록을 지속시키는 게임화 요소. 핵심 문제 해결보다는 서비스 경험 강화에 해당한다. |
| 감정 어휘 기반 캐릭터·아이템 수집 | Could | 감정 어휘 수집과 게임화 경험을 강화할 수 있지만 초기 서비스에서는 필수적이지 않다. |
| 소셜 기능 / 감정 공유 | Won't | 최종 페르소나는 혼자 생각하고 정리하는 성향이며, 감정을 솔직하게 기록할 수 있는 개인적 환경이 중요하다. |
| 전문가 상담·심리상담 연결 | Won't | 서비스의 핵심인 감정 어휘 탐색·표현의 범위를 넘어 서비스 목적이 분산될 수 있다. |
| 복잡한 감정 진단·심리검사 | Won't | 사용자가 직접 감정을 탐색하고 발견하는 것이 핵심이므로 진단 결과를 제공하는 방식과 맞지 않는다. |
| 감정 자동 분석·AI 진단 | Won't | 사용자가 감정 간 관계를 직접 비교하고 자신의 감정을 발견하는 경험이 핵심이므로 자동 판단이 핵심 경험을 대체하지 않도록 한다. |

# **② 사이트맵 작성**

Must \+ Should로 분류된 기능만 화면 단위로 묶어 사이트맵(정적인 화면 계층 구조)을 만듭니다. 사용자가 이동하는 순서(화면 흐름)와는 다른, '어떤 화면들이 있는지'에 대한 지도입니다.

**프롬프트** 

| 방금 분류한 Must \+ Should 기능들을 화면 단위로 묶어서 사이트맵을 만들어줘. 사이트맵은 화면들의 정적인 목록·계층 구조이며(사용자가 이동하는 순서가 아님), 최상위 화면부터 하위 화면까지 트리 구조로 보여주고 각 화면에 어떤 기능이 들어가는지 한 줄씩 설명해줘. |
| :---- |

| 최상위 화면 | 하위 화면 | 포함되는 기능 |
| :---- | :---- | :---- |
| 홈 | 감정 탐색 | 감정 입력, 감정 검색 |
|  | 상황으로 찾기 | 상황 선택·입력, 상황 기반 감정 후보 탐색 |
|  | 감정 단어 예시 | 감정 단어 예시·추천, 막연한 느낌에서 감정 후보 탐색 |
| 감정 어휘 지도 | 감정 지도 | 전체 감정 어휘의 위치와 관계 탐색 |
|  | 감정 영역 탐색 | 감정 영역 탐색, 영역 내 감정 어휘 탐색 |
|  | 감정 관계 탐색 | 유사 감정, 관련 감정, 반대 감정, 감정 간 거리·관계 |
|  | 감정 비교 | 감정 비교, 감정 제외, 다른 영역 탐색 |
| 감정 상세 | 감정 정보 | 감정 의미·정의, 감정 특징 |
|  | 감정 상황 | 감정이 나타나는 상황, 관련 상황 예시 |
|  | 감정 관계 | 유사 감정, 관련 감정, 반대 감정 |
|  | 감정 비교 | 선택한 감정과 다른 감정 비교 |
|  | 감정 표현 | 표현 대상·상황 선택, 표현 문장 추천 |
|  | 이모티콘 | 감정 기반 이모티콘 추천 |
|  | 감정 기록 | 선택한 감정과 상황 기록 |
| 나의 감정 | 감정 기록 | 감정 기록 작성·조회 |
|  | 기록 히스토리 | 과거 감정·상황 기록 조회 |
|  | 감정 리포트 | 자주 느낀 감정, 감정 변화·패턴 |
|  | 감정 도감 | 발견한 감정 어휘, 감정 어휘 수집 현황 |
|  | 뱃지·업적 | 어휘 발견, 영역 발견, 탐색·수집 성취 |

# **③ 검증 — 1\~3단계 원본과 대조하기**

MoSCoW 분류와 사이트맵이 완성되면, 이 결과가 1\~3단계 원본(페르소나·저니맵·컨셉 스테이트먼트)의 핵심 내용을 빠뜨리지 않았는지 대조합니다. 만들기만 하고 넘어가면 AI가 요약 과정에서 놓친 부분을 그대로 안고 다음 단계로 가게 됩니다.

**프롬프트**

| 방금 분류한 MoSCoW 결과와 사이트맵을 1\~3단계 원본 워크시트 파일과 대조해줘. 페르소나의 핵심 목표·페인포인트 중 어떤 기능에도 반영되지 않은 항목이 있는지 확인해줘. 빠진 부분이 있다면 어느 등급(Must/Should/Could)에 추가하면 좋을지 제안해줘. |
| :---- |

| 페르소나 핵심 목표·페인포인트 (원문 출처) | 반영 여부 | 관련 기능/화면 |
| ----- | ----- | ----- |
| 내가 지금 어떤 감정을 느끼고 있는지 정확히 알고 싶다. | 반영됨 | 감정 입력 → 감정 지도 → 감정 영역 → 유사·관련·반대 감정 → 감정 거리·관계 → 감정 비교·제외 → 감정 상세 |
| 그 감정을 나에게 맞는 단어로 표현하고 싶다. | 반영됨 | 감정 탐색 → 감정 상세 → 표현 문장 / 감정 기록 |
| 감정이 복잡하거나 여러 감정이 섞이면 어떤 단어로 표현해야 할지 모호하다. | 반영됨 | 감정 입력 → 유사·관련·반대 감정 → 다른 영역 탐색 → 감정 거리 → 감정 비교·제외 |
