# 감정 어휘 지도 — Design System (v5)

> Global Source of Truth. 모든 화면은 이 문서의 토큰·컴포넌트 규칙을 그대로 따른다.
> Stack: **HTML + Tailwind CSS (CDN Play)**, 폰트/텍스처/레이아웃/노드 스타일은 `design-system/tokens.css` 공용 파일로 공유.
>
> **v4 변경 요약 — 구조를 참고 레퍼런스에 맞춰 재설계 (스타일/토큰은 v3 그대로 유지):**
> 이전 작업에서 이미 설계해둔 초안(`감정 어휘지도 (standalone).html`, Claude 디자인 캔버스 내보내기)의 **정보구조·데이터·인터랙션**을 그대로 들여왔다. 색·서체·컴포넌트 톤 등 "스타일"은 v3를 그대로 유지했다.
> 1. **데이터 대폭 확장** — 손으로 만든 9개 단어 대신 실제 **145개 감정 단어**(정의·예문·일러스트 장면 묘사·강도 1~5·품사·소품 포함) + **203개 관계 엣지** + 9영역 좌표를 전부 반영.
> 2. **3단계 발견 상태** — 이전 "발견/미발견" 이분법을 폐기하고 `숨김(0) → 이웃/미확인(1) → 발견(2)` 3단계로 확장. tier 1은 이미 발견한 단어의 이웃일 때만 나타나는 점선 원이며, 호버해야 이름이 보인다. tier 0은 지도에 존재하지만 상호작용 불가능한 흐릿한 점이다.
> 3. **상세 패널 = 팝업 → 우측 고정 사이드바**로 전환. 지도를 가리지 않고 계속 보면서 상세 내용을 확인한다.
> 4. **관계 모델 세분화** — "유사/관련/반대" 대신 **가까운 감정**(그래프상 직접 연결된 이웃)과 **조금 다른 감정**(다른 영역 + 강도 차이 ≥1인 대조 후보)의 2단 모델로 교체. **감정의 위치**는 해당 영역의 뿌리 단어에서 지금 단어까지 실제 그래프 탐색(BFS) 경로를 보여준다.
> 5. **지도에 팬/줌 인터랙션 추가** — 2700×1850 캔버스를 드래그로 이동, 버튼으로 확대·축소·위치 복귀.
> 6. **"감정 여정"(6개 분리 화면) → "감정 서고"(1개 통합 화면)** 로 정보구조 자체를 압축. 발견/저장/마음기록 통계 탭 + 기간별(일/월/연) 그래프 + 지역 완성도 + 뱃지가 한 페이지에 모인다.
> 7. **localStorage 기반 상태 공유** — 지도에서 발견·저장·기록한 내용이 감정 찾기(홈)·감정 서고에도 그대로 반영된다 (별도 서버 없이 브라우저에 저장, 프로토타입 한정).
> 8. 홈(`find.html`)에 참고 레퍼런스처럼 **2단 레이아웃**(메인 검색+상황카드 / 사이드바: 오늘의 한 단어·영역별 발견 현황·저장·뱃지 통계)을 도입.
>
> **v4.1 보완 (버그 수정 + 다듬기):**
> - **로그인 사용자 표시** — 모든 화면 상단 우측에 `.user-chip`(아바타 이니셜 + 이름 + 온라인 점)을 추가. "이 서비스는 로그인한 한 사람을 위한 공간"임을 항상 보이게 한다.
> - **버튼 패딩 버그 수정** — `.btn-primary`/`.btn-secondary`가 좌우 패딩 없이 정의되어 있어, Tailwind `px-*` 유틸리티를 깜빡한 곳(감정 서고의 두 버튼)에서 글자가 테두리에 붙어 보였다. 두 클래스에 기본 좌우 패딩(24~26px)을 내장해 앞으로는 어디서 써도 깨지지 않는다.
> - **상세 패널 숨김 버그 수정** — `class="hidden"`과 인라인 `style="display:flex"`를 동시에 걸어둬 인라인 스타일이 항상 이겨서 패널이 꺼지지 않던 문제. 이제 `style.display`만으로 여닫아 선택한 단어가 없으면 패널이 완전히 닫혀 있다.
> - **지도 팬/줌 컨트롤 재배치** — 좌상단 "현재 위치" 카드에서 확대/축소/재중심 버튼을 떼어내 우하단에 작은 아이콘 버튼(`.map-tool-btn`, 32px)으로 옮기고, 그 위에 나침반(N) 장식을 되살렸다.
> - **영역 겹침 대응** — 영역 타원에 `mix-blend-mode:multiply`를 적용해, 혹시 영역이 겹치는 자리가 생기면 두 색이 자연스럽게 번져 보이도록 했다(현재 좌표에서는 실제로 겹치지 않지만 방어적으로 대비). 개념적으로는 **영역 간 경계에 걸친 감정은 그래프 엣지(단어 간 연결)가 이미 표현하고 있다** — 예: `dapdap`(분노)↔`huryeon`(기쁨)처럼 서로 다른 영역을 잇는 엣지가 있으면, 그 단어는 두 영역 모두와 관계있다는 뜻으로 읽으면 된다. 위치는 하나의 영역에 속하되, 관계선이 다른 영역까지 뻗어나가는 방식으로 "겹침"을 표현한다.
> - **관계 모델에 반의어 추가** — §3.2 "가까운 감정"에 그래프 홉(hop) 기반 **거리 %**(1촌 92%, 2촌 74%, 3촌 56% …)를 노출했고, "조금 다른 감정"에서 가장 강도 대비가 큰 단어 하나를 **반의어**로 명시적으로 분리했다(규칙: 다른 영역 + 강도차 최대, id 알파벳순 동점 처리 — 145개 전 단어에 결정적으로 적용되는 계산 규칙이며 수작업 사전이 아니다).
> - **홈 화면 리디자인** — "예쁘지 않다"는 피드백에 따라 불필요한 정보(중복된 "지도 조각" 칩, 정적 "검색 결과" 데모 카드)를 걷어내고, 히어로 헤드라인과 오늘의 단어에 한정해 **세리프 서체**(`.font-display-serif`, Noto Serif KR)를 예외적으로 허용했다 — 나머지 UI 전반의 "한글은 전부 Pretendard" 원칙은 유지된다. 상황 카드는 11개 → 6개로 줄이고, 실사용 데이터를 쌓겠다는 방향에 맞춰 **"요즘 사람들이 많이 찾는 감정"** 랭킹 섹션을 새로 넣었다(현재는 예시 수치).
>
> **v4.2 정리 — 파일 구조 평탄화 + 실제 반응형 대응:**
> - **파일 구조 단순화** — `screens/` 폴더를 없애고 `find.html`·`map.html`·`archive.html`을 전부 루트로 옮겼다. `find.html`은 루트 `index.html`이 되어 리다이렉트 파일이 따로 필요 없어졌고(사이트 주소로 바로 들어오면 감정 찾기가 즉시 뜬다), 아무 데서도 링크되지 않던(=고아 상태였던) 전체 흐름 소개 화면(`screens/index.html`)은 삭제했다(사용자가 별도 랜딩 페이지를 만들 예정). 참고용으로만 남아 있던 13.6MB짜리 `감정 어휘지도 (standalone).html`도 함께 정리했다.
> - **실제 모바일 대응** — 지금까지 "웹 우선, 데스크톱 기준 반응형"이라고만 적어두고 실제로는 데스크톱 레이아웃뿐이었다. 이번에 진짜로 손봤다: 상단 내비게이션은 좁은 화면에서 글자·여백을 줄이고 그래도 안 들어가면 메뉴만 가로 스와이프되게 했고, 홈의 2단 레이아웃(입력창+사이드바)은 `md` 미만에서 1단으로 쌓이며, 지도 화면의 우측 상세 패널(`focus-panel`)은 760px 이하에서 화면 대부분을 덮는 시트로 전환된다. **가장 중요한 변화는 지도의 터치 지원** — 이전에는 마우스 드래그·휠로만 팬/줌이 가능해 터치스크린에서는 지도를 아예 조작할 수 없었는데, 한 손가락 드래그(팬)와 두 손가락 핀치(줌)를 추가해 실제로 폰·태블릿에서 지도가 동작하게 됐다.
> - **문서 이름 변경** — 이 문서(`MASTER.md`)는 `DESIGN.md`로 이름을 바꿨다. 내용이 곧 디자인 시스템 문서라 "MASTER"보다 용도가 더 분명하게 드러난다.
>
> **v5 — 목업 161개 전량 폐기, HuggingFace 실제 데이터 434개로 전면 교체:**
> - 지금까지의 161개 단어는 화면을 채우던 가짜 목업이었다. HuggingFace 한국어 감정 어휘 데이터셋(434개, CC0)에서 실제 뜻·품사에 맞는 단어를 골라 전부 교체했다. 선별 기준·영역 재분류 방법은 `docs/감정지도_어휘기준.md`에 정리해뒀다.
> - **2단계로 진행** — 1차로 품질 지표(representative 또는 prototypicality·familiarity 중앙값 이상) 통과분 204개를 먼저 채우고, 2차로 나머지 230개를 마저 채워 최종 434개를 완성했다.
> - **통계 분류의 한계를 사람이 직접 보정** — valence·arousal 최근접 중심점(nearest-centroid) 분류만 믿고 넘어가지 않고, 434개 전체를 사람이 다시 읽고 검토했다. 특히 "분노의 영역"↔"혐오의 늪" 중심점이 지나치게 가까워서, 통계만으로는 "화나다"·"분노하다"·"격노하다" 같은 명백한 분노 단어까지 혐오의 늪으로 잘못 분류되는 문제가 반복적으로 나타났다 — 434개 중 약 절반(204개 중 66개, 230개 중 116개)을 이런 식으로 재배정했다.
> - **관계 엣지 620개 신규 생성** — 옛 223개 엣지는 삭제된 단어를 참조해 전량 폐기하고, 영역별로 valence·arousal 거리 기반 최소 신장 트리(MST) + 최근접 이웃 2개를 합쳐 새로 만들었다. 모든 영역이 뿌리 단어에서 전 단어까지 연결되는 것을 BFS로 검증했다.
> - **영역 크기 재조정** — 단어 수가 영역마다 14~70개로 크게 벌어져(예: 분노 70개 vs 평온 14개) 기존처럼 전 영역 `rx=400` 균일 크기를 쓰면 밀도가 안 맞았다. 전체 영역 단어 수의 중앙값(45.5개) 대비 `sqrt(해당 영역 단어 수 / 45.5)` 배율로 `rx`/`ry`를 영역마다 다르게 재계산하고, 겹치지 않도록 좌표 격자 전체를 재배치했다(캔버스 2700×2500 → **3156×2588**). §3.1.1에 계산 방식을 남겨뒀다.

## 0. 이 디자인이 어디서 왔는가 (근거)

| 페르소나/워크시트 근거 | 디자인 결정으로 번역 |
|---|---|
| "일기도 결국 누군가 볼 수 있기 때문에 솔직하기 어렵다" (인터뷰) | 완전히 사적이고 조용한 톤. 소셜 요소·공유 유도 없음 |
| 이준호 — "혼자 생각하고 자신을 돌아보는 시간을 중요하게 여긴다" | 쾌활한 게이미피케이션 배제, 사색적인 무드 |
| "감정이 복잡하게 섞이면… 단어 하나로 정의하기 어렵다" | 감정을 하나의 정답이 아니라 **지도 위 위치·관계**로 표현 |
| "지금의 마음을 한 줄 적으면, 그 마음이 놓인 자리를 지도에서 찾아준다. 하나의 감정에서 멈추지 말고, 이어진 길을 따라 더 정확한 단어를 발견한다" (v3 피드백) | 지도를 **정적인 영역 지도**가 아니라 **탐색할수록 확장되는 노드 그래프**로 재정의. 감정 찾기 → 지도 진입 → 노드를 따라 발견을 이어가는 흐름이 핵심 경험 |
| 컨셉명 "감정 어휘 지도" | 노드(감정 단어) + 엣지(관계) + 영역(10영역, 배경) 3층 구조의 지도 |

**한 문장 컨셉:** *"햇살 드는 오후, 책상 위에 펼쳐 둔 감정의 지도 — 한 단어에서 시작해 이어진 길을 따라 더 정확한 단어를 발견한다."*

**경쟁사 대비 의도적 회피 (Anti-pattern):**
- ❌ Finch류 — 캐릭터를 키우고 꾸미고 레벨업시키는 성장형 마스코트 (4단계 MoSCoW "캐릭터 성장·꾸미기"·"캐릭터·아이템 수집"은 Could 등급, 배제)
- ❌ How We Feel류 — 임상적 흰 배경 + 파랑, 설문지 같은 딱딱한 폼
- ❌ Daylio류 — 이모지 그리드 중심의 즉석 체크 UI
- ✅ 대신: 따뜻한 종이빛 배경, 손그림 지형 위 노드-엣지 그래프, 굵은 Pretendard 제목 + 모노스페이스 좌표

**캐릭터에 대한 구분 (유지):**
| 구분 | 등급 | 채택 여부 |
|---|---|---|
| 캐릭터 = 감정 이모티콘 (그 순간의 감정을 표정으로 담은 정적 스티커) | Should | ✅ 채택 |
| 캐릭터 = 성장·꾸미기·수집 대상 | Could | ❌ 배제 |

## 1. 톤 & 플랫폼 — "햇살 드는 오후의 책상"

다크 "야간 열람실" 테마를 폐기하고, **따뜻하고 밝은 라이트 테마**로 전환한다. 책상 위에 펼쳐 둔 종이 지도에 오후 햇살이 비스듬히 드는 이미지.

- **웹 우선**, 모바일·태블릿까지 포함한 반응형 (v4.2: 데스크톱 전용에서 확장 — 상단바·2단 레이아웃·지도 상세 패널이 좁은 화면에 맞게 재배치되고, 지도는 터치 팬/핀치줌을 지원한다).
- **상단 내비게이션** (v3 신규) — 사이드바 폐기. 로고 + 3대 메뉴가 화면 최상단에 고정.
- **감정 지도는 전체 화면** — 좌우 분할 없이 지도 자체가 콘텐츠 영역 전체를 채운다. 상세는 팝업으로 그 위에 뜬다.

```
┌──────────────────────────────────────────────────────────┐
│ 감정 어휘 지도(→홈)      감정 찾기   감정 지도   감정 여정   │  ← topbar, 고정
├──────────────────────────────────────────────────────────┤
│                                                              │
│                     (감정 지도 화면: 전체 화면 그래프)         │
│                                                              │
└──────────────────────────────────────────────────────────┘
```

### 컬러 토큰
```
--bg-base:        #E8E6D2   /* 종이 위 오후 햇살 — 따뜻한 크림 */
--bg-elevated:     #FFFFFF   /* 카드/팝업 표면 */
--bg-elevated-2:   #E3E1DA   /* 눌림/입력 표면, 책상 나무결에 가까운 톤 */
```

## 3. 감정 지도 — 데이터 기반 팬/줌 그래프 (v4 재설계)

`map.html` 단일 화면이 지도·관계 탐색·비교·상세·표현을 전부 담당하는 구조는 v3에서 유지하되, 내부를 참고 레퍼런스 수준으로 확장했다.

### 3.1 지도 구조
1. **캔버스** — 3156×2588 좌표계(v5: 434개 전체 반영 + 영역별 크기 재조정으로 2700×2500에서 확장, §3.1.1 하단 참고), `.map-canvas-wrap`(뷰포트, 드래그로 팬 + 모바일은 터치 팬) 안에 `.map-canvas`(CSS `transform: translate() scale()`로 팬/줌 적용)가 들어있다. 좌측 상단 도구 패널에 확대·축소·"위치로 되돌리기" 버튼이 있다.
2. **영역(배경)** — 10개 타원, 각 `REGIONS` 항목의 `cx/cy/rx/ry` + 우리 색 팔레트의 옅은 워시(12~20% opacity) + 점선 테두리. `rx`/`ry`는 v5부터 전 영역 균일(400)이 아니라 영역별 단어 수에 비례해 다르다(§3.1.1 하단). 해당 영역에 발견된 단어가 1개라도 있으면 워시가 살짝 진해지고 라벨이 더 또렷해진다.
3. **엣지(관계)** — `EDGE_PAIRS` 620개(v5: 영역별 valence·arousal 거리 기반 최소 신장 트리 + 최근접 이웃 2개로 신규 생성, §5 데이터 소스 참고). 양쪽 다 발견 → 실선, 한쪽이라도 tier≥1(닿을 수 있는 상태) → 점선, 둘 다 tier 0 → 렌더링하지 않음(잡음 제거).
4. **노드(단어)** — `WORD_ROWS` 434개, 영역 안에서 골든 앵글 스파이럴로 자동 배치(겹치지 않게, 알고리즘은 §3.1.1 참고. 단 경계에 걸친 단어 130개는 예외 — §3.1.1 하단 참고). **3단계 발견 상태**:
   - **tier 0 (숨김)**: 흐린 점, 상호작용 불가(`pointer-events:none`).
   - **tier 1 (이웃/미확인)**: 점선 원, 라벨은 호버해야 보임. 이미 발견한 단어의 그래프 이웃일 때만 이 상태가 된다.
   - **tier 2 (발견)**: 영역색으로 채워짐, 라벨 항상 노출.
   - **클릭**: tier 1 노드를 클릭하면 발견 처리(tier 2로 전환 + 연결 엣지 실선화)와 동시에 우측 상세 패널이 열린다.

### 3.1.1 단어 배치 알고리즘 — 골든 앵글 스파이럴 (재구현 시 반드시 참고)

영역 하나에 단어가 14~70개(v5, 영역마다 편차 큼)씩 있는데, 이걸 겹치지 않고 자연스럽게 흩뿌리기 위해 "골든 앵글 스파이럴"(phyllotactic spiral / Vogel's model)을 쓴다. 이 프로젝트에서 새로 만든 공식이 아니라, 해바라기 씨앗·솔방울 비늘이 배열되는 원리를 1979년 헬무트 포겔(Helmut Vogel)이 정리한 공개된 수학 공식이다. 사이트를 다시 만들게 되더라도 아래 4줄만 그대로 옮기면 동일한 배치를 재현할 수 있다.

```js
// n = 해당 영역에 속한 단어 개수, i = 영역 내 단어의 순서(0부터 시작)
const t = Math.sqrt((i + 0.55) / n);
const angle = i * 2.39996323; // 골든 앵글(약 137.5도)의 라디안 값
w._x = region.cx + region.rx * t * Math.cos(angle) * 0.82;
w._y = region.cy + region.ry * t * Math.sin(angle) * 0.82;
```

**각 숫자가 뭘 하는지**
- `angle = i * 2.39996323` — 단어마다 정확히 "골든 앵글"(황금각, 360°/φ² ≈ 137.5077°)만큼씩 돌린다. 이 각도는 무리수 비율이라 아무리 반복해도 이전 점과 같은 방향으로 겹치지 않는다 — 90°나 120°처럼 딱 떨어지는 각도를 쓰면 점들이 방사형 "줄"을 그리며 뭉친다.
- `t = Math.sqrt((i + 0.55) / n)` — 중심에서 얼마나 멀리 떨어질지(반지름 비율, 0~1). `i`를 그대로 쓰지 않고 **제곱근**을 쓰는 이유: 바깥으로 갈수록 원둘레가 넓어지는 만큼 반지름도 더 빨리 벌어져야 안쪽·바깥쪽 점 밀도가 똑같이 유지된다. `+0.55`는 첫 단어(i=0)가 영역 정중앙에 딱 붙지 않고 살짝 떨어져 시작하게 하는 보정값이다.
- `* 0.82` — 계산된 반지름에 곱해서, 가장 바깥쪽 단어도 영역 타원 테두리 안쪽에 여유 있게 들어오게 한다.
- `region.rx`/`region.ry`를 각각 곱하는 이유 — 영역이 정원이 아니라 가로로 넓은 타원이라, x·y축 배율을 다르게 줘서 타원 모양에 맞게 늘어나게 한다.

**왜 이 방식을 쓰는지**
- **결정적(deterministic)**: 무작위가 아니라 순서(`i`)와 개수(`n`)만으로 위치가 정해져서, 새로고침해도 발견한 단어의 위치가 안 바뀐다.
- **단어 수가 바뀌어도 자동 재배치**: v4.3에서 "혐오의 늪"에 13개 단어를 추가할 때도 좌표를 하나씩 손으로 정하지 않고 이 공식 하나로 해결했다. 앞으로 어떤 영역에 단어를 더 추가하거나 빼도 이 로직만 그대로 두면 알아서 다시 계산된다.
- **겹침이 없다**: 격자 배치나 무작위 배치와 달리 점들이 서로 겹치거나 한쪽에 몰리지 않는다.

**재구현 시 참고**: 특정 프레임워크에 종속된 기법이 아니라 "N개의 점을 원(타원) 안에 겹치지 않게 흩뿌리기"라는 일반적인 문제의 표준 해법이라, React·Canvas·D3 등 다른 렌더링 방식으로 옮겨 만들어도 위 4줄 공식만 그대로 이식하면 동일한 배치 결과를 재현할 수 있다.

**예외 — 경계에 걸친 단어(v4.3에서 도입, v5에서 130개로 확대)**: 경멸하다·우쭐하다·비장하다처럼 "영역 소속은 유지하되 시각적으로는 이웃 영역 쪽 경계 밖으로 살짝 걸치게" 표현해야 하는 단어는 위 스파이럴 공식이 아니라 별도 조회 테이블 `EDGE_BIAS = { 단어id: '이웃영역id' }`로 처리한다. 스파이럴의 `t`(반지름 비율)·`angle`을 계산하는 대신, `atan2(이웃영역.cy - 내영역.cy, 이웃영역.cx - 내영역.cx)`로 "내 영역 중심에서 이웃 영역 중심을 바라보는 각도"를 구한다. 반지름 비율은 **1.1**을 쓰는데, 일반 단어는 전부 `*0.82`가 곱해져 테두리(비율 1.0) 안쪽에 머무는 것과 달리, 경계 단어는 이 배율을 아예 빼고 1.1을 곱해 테두리보다 바깥(대략 테두리에서 20~40px 정도)으로 나가게 한다 — 처음에는 0.82를 그대로 곱한 채 0.97을 썼다가 여전히 테두리 안쪽(비율 0.795)에 머무는 버그가 있어서 고쳤다. 즉 스파이럴은 "영역 안을 고르게 채우기" 문제의 해법이고, `EDGE_BIAS`는 "이 단어만 테두리 밖 특정 방향으로 밀어내기"라는 별개의 문제라 서로 다른 공식을 쓴다 — 재구현할 때도 이 둘을 하나로 합치려 하지 말고 분리해서 옮기는 게 안전하다. v5에서는 HuggingFace 434개를 영역 분류할 때 1·2등 후보 거리차가 작았던 130개 단어에 이 메커니즘을 그대로 확장 적용했다(기준은 `docs/감정지도_어휘기준.md` §2 참고).

**영역 크기(rx/ry) 계산 — 단어 수 편차가 클 때(v5 신규)**: 434개를 10개 영역에 나누니 영역마다 14~70개로 편차가 커져서, 예전처럼 `rx=400` 하나로 전 영역을 통일하면 분노의 영역(70개)은 빽빽하고 평온의 호수(14개)는 헐렁해 보였다. 그래서 각 영역의 `rx`/`ry`를 아래 공식으로 다시 계산했다.

```js
// medianCount = 10개 영역 단어 수의 중앙값(v5 기준 45.5개)
// baseRx = 400, baseRy = 그 영역의 기존 ry 값(타원 비율 유지)
const scale = Math.sqrt(regionWordCount / medianCount);
const rx = baseRx * scale;
const ry = baseRy * scale;
```

중앙값(전체 평균이 아니라)을 기준으로 잡은 이유는, 절반은 커지고 절반은 작아지도록 스케일이 중앙에서 갈라지게 하기 위해서다 — 가장 작은 old baseline(예: 13개)을 기준으로 스케일을 잡으면 큰 영역이 지나치게 커져서(70/13 ≈ 5.4배) 캔버스가 감당 못 할 만큼 넓어진다. 중앙값 기준으로는 최대 배율이 약 1.24배(분노), 최소가 약 0.55배(평온)로 훨씬 완만하다. 이렇게 계산한 `rx`/`ry`로 좌표 격자(각 영역의 `cx`/`cy`)도 겹치지 않도록 전부 다시 배치했고, 그 결과 캔버스 전체 크기가 2700×2500 → 3156×2588로 늘었다(가로 17%, 세로 4%). 다음에 단어가 더 늘어나면(예: 언젠가 어휘를 추가로 확장할 때) 이 공식을 그대로 다시 돌리고 좌표 격자만 겹치지 않게 재배치하면 된다.

### 3.2 상세 패널 — 우측 고정 사이드바 (v4: 팝업 → 패널)
지도를 가리지 않도록 화면 우측에 고정된 패널로 바뀌었다. 담는 내용:
1. 헤더: 영역명 + 단어명(Pretendard Bold) + 품사 + 닫기 버튼
2. **감정 캐릭터**: 단어의 영역색으로 물든 캐릭터 일러스트 + 소품(`prop`: book/letter/map은 작은 카드, flower는 꽃 점 셋, none은 아무것도 없음) + 그 단어만의 장면 묘사 텍스트
3. 의미(`def`) · **감정 강도**(1~5 바 게이지 + 라벨)
4. **가까운 감정** (그래프 직접 이웃, 최대 4개, 칩 클릭 시 그 단어로 이동+발견) / **조금 다른 감정** (다른 영역 + 강도차 ≥1인 대조 후보, 점선 칩)
5. **감정의 위치**: 영역의 뿌리 단어(`root`)에서 지금 단어까지, 발견된 그래프만 통과하는 실제 BFS 최단 경로를 화살표로 표시
6. 표현 문장(`say`) + 복사 버튼
7. **마음 기록**: 이 단어에 대한 메모 작성(저장 시 감정 서고에 누적) + 이 단어의 기존 기록 목록
8. **저장/저장 취소** 토글 (감정 서고의 "저장한 단어"에 반영)

### 3.3 상태 저장 (v4 신규)
발견/저장/기록은 `localStorage`(`ewm_store_v1`)에 저장되어 `index.html`·`map.html`·`archive.html` 세 화면이 같은 상태를 공유한다. 서버 없는 프로토타입이므로 브라우저를 바꾸면 초기화된다.

### 3.4 시각 규칙
- 노드 반경·라벨 크기·엣지 두께는 상태와 무관하게 거의 동일 — **채움/테두리, 실선/점선, 라벨 노출 여부**로만 상태를 구분한다(색맹 사용자도 형태로 구분 가능).

## 4. 타이포그래피 · 스페이싱 · 모션 · 접근성

- **서체:** 한글 UI 텍스트는 기본적으로 **전부 Pretendard**를 쓴다 — `.font-serif-kr`/`.topbar-brand`는 `font-weight:700`의 Pretendard로 위계를 준다. **IBM Plex Mono는 한글이 아닌 좌표·청구기호(`SAD·07`, `37.5°S` 등 라틴/숫자 라벨)에만 한정**해서 쓴다.
  **예외(v4.1):** 홈(`index.html`)의 히어로 헤드라인·오늘의 단어·영역 이름처럼 "한 순간의 우아함"이 필요한 딱 몇 곳에는 `.font-display-serif`(Noto Serif KR)를 의도적으로 쓴다. 이 예외는 홈 화면에 한정하고, 지도·서고 등 나머지 화면에는 확대 적용하지 않는다.
- 라운딩: `sm 10px · md 20px · lg 28px · pill 999px` — 동일.
- 그림자: 다크에서 쓰던 블랙 글로우 대신 **따뜻한 갈색 계열 소프트 섀도**(`0 8px 20px -8px rgba(38,36,32,.14)`) — 책상 위에 놓인 종이 느낌.
- 모션: 200–260ms ease-out 페이드업 동일. 발견 노드는 `pulse-glow` 3s. `prefers-reduced-motion`에서 정지.

### 데이터 소스
`index.html`·`map.html`·`archive.html` 세 파일 모두 동일한 434단어/10영역/620엣지 데이터를 각자 인라인 `<script>`로 갖고 있다(빌드 단계가 없는 정적 프로토타입이라 파일 간 공유 대신 중복 — `index.html`과 `archive.html`은 필요한 필드만 축약한 버전을 쓴다). 원본 9영역·145단어는 이전 작업에서 만든 초안 파일 `감정 어휘지도 (standalone).html`에서 그대로 옮겨왔다(이 파일 자체는 내용이 이미 세 화면에 다 이식된 뒤 v4.2에서 삭제했다). v4.3에서 10번째 영역(혐오의 늪)과 "분노의 영역" 경계 단어 3개를 직접 작성해 추가했었지만, 이때까지의 단어(161개)는 모두 화면을 채우기 위한 가짜 목업이었다.

**v5에서 161개 목업 전량 폐기 → HuggingFace 434개 실제 데이터로 교체**했다. 선별·분류 기준은 `docs/감정지도_어휘기준.md`에 정리했고, 요약하면: ① HuggingFace 한국어 감정 어휘 434개(원본 868행에서 중복 제거) 중 품질 지표(representative 또는 prototypicality·familiarity 중앙값 이상)를 통과한 순서로 204개→230개, 2단계로 나눠 채웠다. ② valence·arousal 최근접 중심점 분류만 쓰지 않고 사람이 434개 전부를 다시 읽어 절반가량을 재배정했다(분노↔혐오 중심점이 너무 가까워 통계만으로는 "화나다" 같은 명백한 단어까지 잘못 분류되는 문제가 반복됐다). ③ 뜻풀이·예문·캐릭터 장면은 KOTE·EVOKE 원문을 베끼지 않고(둘 다 CC BY-NC 라이선스) 전부 새로 썼다. ④ 관계 엣지 620개는 영역별 valence·arousal 거리 기반 최소 신장 트리 + 최근접 이웃 2개로 새로 계산했다(옛 223개는 삭제된 단어를 참조해 폐기).

## 6. 감정 어휘 확장 — 진행 상황

> 아래 표는 v4.3 당시(10번째 영역 신설 결정) 기록이라 단어 개수 등 일부 수치는 v5(434개 전체 교체) 이후 달라졌다. 결정 자체(10번째 영역 신설, 경계 단어 처리 방식, "깨달음" 미영역화)는 그대로 유효하므로 역사적 기록으로 남겨둔다. v5 이후의 전체 최신 통계는 §3.1·§5, 상세 방법론은 `docs/감정지도_어휘기준.md` 참고.

KOTE(43개 한국어 감정 분류)와 HuggingFace의 감정 어휘 데이터(valence/arousal 실측치, CC0)를 기존 9개 영역과 대조해 다음 세 가지를 결정했다. 아래 표로 진행 상황을 구분한다.

|---|---|---|
| **10번째 영역 추가 — "혐오의 늪"** | KOTE 43개 분류 중 "역겨움/혐오"는 기존 9개 영역 어디에도 자연스럽게 안 맞았다(화남·짜증 계열과는 결이 다름).
