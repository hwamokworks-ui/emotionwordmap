# 감정 어휘 지도 — Design System MASTER (v4)

> Global Source of Truth. 모든 화면은 이 문서의 토큰·컴포넌트 규칙을 그대로 따른다.
> Stack: **HTML + Tailwind CSS (CDN Play)**, 폰트/텍스처/레이아웃/노드 스타일은 `design-system/tokens.css` 공용 파일로 공유.
>
> **v4 변경 요약 — 구조를 참고 레퍼런스에 맞춰 재설계 (스타일/토큰은 v3 그대로 유지):**
> 사용자가 제공한 참고 파일(`감정 어휘지도 (standalone).html`, Claude 디자인 캔버스 내보내기)의 **정보구조·데이터·인터랙션**을 그대로 들여왔다. 색·서체·컴포넌트 톤 등 "스타일"은 v3를 그대로 유지했다.
> 1. **데이터 대폭 확장** — 손으로 만든 9개 단어 대신 실제 **145개 감정 단어**(정의·예문·일러스트 장면 묘사·강도 1~5·품사·소품 포함) + **203개 관계 엣지** + 9영역 좌표를 전부 반영.
> 2. **3단계 발견 상태** — 이전 "발견/미발견" 이분법을 폐기하고 `숨김(0) → 이웃/미확인(1) → 발견(2)` 3단계로 확장. tier 1은 이미 발견한 단어의 이웃일 때만 나타나는 점선 원이며, 호버해야 이름이 보인다. tier 0은 지도에 존재하지만 상호작용 불가능한 흐릿한 점이다.
> 3. **상세 패널 = 팝업 → 우측 고정 사이드바**로 전환. 지도를 가리지 않고 계속 보면서 상세 내용을 확인한다.
> 4. **관계 모델 세분화** — "유사/관련/반대" 대신 **가까운 감정**(그래프상 직접 연결된 이웃)과 **조금 다른 감정**(다른 영역 + 강도 차이 ≥1인 대조 후보)의 2단 모델로 교체. **감정의 위치**는 해당 영역의 뿌리 단어에서 지금 단어까지 실제 그래프 탐색(BFS) 경로를 보여준다.
> 5. **지도에 팬/줌 인터랙션 추가** — 2700×1850 캔버스를 드래그로 이동, 버튼으로 확대·축소·위치 복귀.
> 6. **"감정 여정"(6개 분리 화면) → "감정 서고"(1개 통합 화면)** 로 정보구조 자체를 압축. 발견/저장/마음기록 통계 탭 + 기간별(일/월/연) 그래프 + 지역 완성도 + 뱃지가 한 페이지에 모인다.
> 7. **localStorage 기반 상태 공유** — 지도에서 발견·저장·기록한 내용이 감정 찾기(홈)·감정 서고에도 그대로 반영된다 (별도 서버 없이 브라우저에 저장, 프로토타입 한정).
> 8. 홈(`find.html`)에 참고 레퍼런스처럼 **2단 레이아웃**(메인 검색+상황카드 / 사이드바: 오늘의 한 단어·영역별 발견 현황·저장·뱃지 통계)을 도입.
>
> **v4.1 보완 (버그 수정 + 다듬기):**
> - **로그인 사용자 표시** — 모든 화면 상단 우측에 `.user-chip`(아바타 이니셜 + 이름 + 온라인 점)을 추가. "이 서비스는 로그인한 한 사람을 위한 공간"임을 항상 보이게 한다.
> - **버튼 패딩 버그 수정** — `.btn-primary`/`.btn-secondary`가 좌우 패딩 없이 정의되어 있어, Tailwind `px-*` 유틸리티를 깜빡한 곳(감정 서고의 두 버튼)에서 글자가 테두리에 붙어 보였다. 두 클래스에 기본 좌우 패딩(24~26px)을 내장해 앞으로는 어디서 써도 깨지지 않는다.
> - **상세 패널 숨김 버그 수정** — `class="hidden"`과 인라인 `style="display:flex"`를 동시에 걸어둬 인라인 스타일이 항상 이겨서 패널이 꺼지지 않던 문제. 이제 `style.display`만으로 여닫아 선택한 단어가 없으면 패널이 완전히 닫혀 있다.
> - **지도 팬/줌 컨트롤 재배치** — 좌상단 "현재 위치" 카드에서 확대/축소/재중심 버튼을 떼어내 우하단에 작은 아이콘 버튼(`.map-tool-btn`, 32px)으로 옮기고, 그 위에 나침반(N) 장식을 되살렸다.
> - **영역 겹침 대응** — 영역 타원에 `mix-blend-mode:multiply`를 적용해, 혹시 영역이 겹치는 자리가 생기면 두 색이 자연스럽게 번져 보이도록 했다(현재 좌표에서는 실제로 겹치지 않지만 방어적으로 대비). 개념적으로는 **영역 간 경계에 걸친 감정은 그래프 엣지(단어 간 연결)가 이미 표현하고 있다** — 예: `dapdap`(분노)↔`huryeon`(기쁨)처럼 서로 다른 영역을 잇는 엣지가 있으면, 그 단어는 두 영역 모두와 관계있다는 뜻으로 읽으면 된다. 위치는 하나의 영역에 속하되, 관계선이 다른 영역까지 뻗어나가는 방식으로 "겹침"을 표현한다.
> - **관계 모델에 반의어 추가** — §3.2 "가까운 감정"에 그래프 홉(hop) 기반 **거리 %**(1촌 92%, 2촌 74%, 3촌 56% …)를 노출했고, "조금 다른 감정"에서 가장 강도 대비가 큰 단어 하나를 **반의어**로 명시적으로 분리했다(규칙: 다른 영역 + 강도차 최대, id 알파벳순 동점 처리 — 145개 전 단어에 결정적으로 적용되는 계산 규칙이며 수작업 사전이 아니다).
> - **홈 화면 리디자인** — "예쁘지 않다"는 피드백에 따라 불필요한 정보(중복된 "지도 조각" 칩, 정적 "검색 결과" 데모 카드)를 걷어내고, 히어로 헤드라인과 오늘의 단어에 한정해 **세리프 서체**(`.font-display-serif`, Noto Serif KR)를 예외적으로 허용했다 — 나머지 UI 전반의 "한글은 전부 Pretendard" 원칙은 유지된다. 상황 카드는 11개 → 6개로 줄이고, 실사용 데이터를 쌓겠다는 방향에 맞춰 **"요즘 사람들이 많이 찾는 감정"** 랭킹 섹션을 새로 넣었다(현재는 예시 수치).

## 0. 이 디자인이 어디서 왔는가 (근거)

| 페르소나/워크시트 근거 | 디자인 결정으로 번역 |
|---|---|
| "일기도 결국 누군가 볼 수 있기 때문에 솔직하기 어렵다" (인터뷰) | 완전히 사적이고 조용한 톤. 소셜 요소·공유 유도 없음 |
| 이준호 — "혼자 생각하고 자신을 돌아보는 시간을 중요하게 여긴다" | 쾌활한 게이미피케이션 배제, 사색적인 무드 |
| "감정이 복잡하게 섞이면… 단어 하나로 정의하기 어렵다" | 감정을 하나의 정답이 아니라 **지도 위 위치·관계**로 표현 |
| "지금의 마음을 한 줄 적으면, 그 마음이 놓인 자리를 지도에서 찾아준다. 하나의 감정에서 멈추지 말고, 이어진 길을 따라 더 정확한 단어를 발견한다" (v3 피드백) | 지도를 **정적인 영역 지도**가 아니라 **탐색할수록 확장되는 노드 그래프**로 재정의. 감정 찾기 → 지도 진입 → 노드를 따라 발견을 이어가는 흐름이 핵심 경험 |
| 컨셉명 "감정 어휘 지도" | 노드(감정 단어) + 엣지(관계) + 영역(9영역, 배경) 3층 구조의 지도 |

**한 문장 컨셉:** *"햇살 드는 오후, 책상 위에 펼쳐 둔 감정의 지도 — 한 단어에서 시작해 이어진 길을 따라 더 정확한 단어를 발견한다."*

**경쟁사 대비 의도적 회피 (Anti-pattern):**
- ❌ Finch류 — 캐릭터를 키우고 꾸미고 레벨업시키는 성장형 마스코트 (4단계 MoSCoW "캐릭터 성장·꾸미기"·"캐릭터·아이템 수집"은 Could 등급, 배제)
- ❌ How We Feel류 — 임상적 흰 배경 + 파랑, 설문지 같은 딱딱한 폼
- ❌ Daylio류 — 이모지 그리드 중심의 즉석 체크 UI
- ✅ 대신: 따뜻한 종이빛 배경, 손그림 지형 위 노드-엣지 그래프, 굵은 Pretendard 제목 + 모노스페이스 좌표

**캐릭터에 대한 구분 (유지):**
| 구분 | 등급 | 채택 여부 |
|---|---|---|
| 캐릭터 = 감정 이모티콘 (그 순간의 감정을 표정으로 담은 정적 스티커) | Should | ✅ 채택 |
| 캐릭터 = 성장·꾸미기·수집 대상 | Could | ❌ 배제 |

## 1. 톤 & 플랫폼 — "햇살 드는 오후의 책상"

다크 "야간 열람실" 테마를 폐기하고, **따뜻하고 밝은 라이트 테마**로 전환한다. 책상 위에 펼쳐 둔 종이 지도에 오후 햇살이 비스듬히 드는 이미지.

- **웹 우선**, 데스크톱 기준 반응형 (v2에서 유지).
- **상단 내비게이션** (v3 신규) — 사이드바 폐기. 로고 + 3대 메뉴가 화면 최상단에 고정.
- **감정 지도는 전체 화면** — 좌우 분할 없이 지도 자체가 콘텐츠 영역 전체를 채운다. 상세는 팝업으로 그 위에 뜬다.

```
┌──────────────────────────────────────────────────────────┐
│ 감정 어휘 지도(→홈)      감정 찾기   감정 지도   감정 여정   │  ← topbar, 고정
├──────────────────────────────────────────────────────────┤
│                                                              │
│                     (감정 지도 화면: 전체 화면 그래프)         │
│                                                              │
└──────────────────────────────────────────────────────────┘
```

## 2. 상단 내비게이션 (v3 신규 — 사이드바 대체)

```html
<header class="topbar">
  <a href="find.html" class="topbar-brand">감정 어휘 지도</a>
  <nav class="topbar-nav">
    <a href="find.html" class="[active]">감정 찾기</a>
    <a href="map.html" class="[active]">감정 지도</a>
    <a href="archive.html" class="[active]">감정 서고</a>
  </nav>
</header>
```
- 로고(`topbar-brand`)는 항상 `find.html`(홈)로 연결 — "감정 찾기가 곧 홈"이라는 규칙.
- v4에서 3번째 메뉴명이 "감정 여정" → **"감정 서고"**로 바뀌었다 — 6개로 나뉘어 있던 화면이 `archive.html` 하나로 통합되며 참고 레퍼런스의 명칭을 그대로 따랐다(§5 참고).

## 3. 감정 지도 — 데이터 기반 팬/줌 그래프 (v4 재설계)

`map.html` 단일 화면이 지도·관계 탐색·비교·상세·표현을 전부 담당하는 구조는 v3에서 유지하되, 내부를 참고 레퍼런스 수준으로 확장했다.

### 3.1 지도 구조
1. **캔버스** — 2700×1850 좌표계, `.map-canvas-wrap`(뷰포트, 드래그로 팬) 안에 `.map-canvas`(CSS `transform: translate() scale()`로 팬/줌 적용)가 들어있다. 좌측 상단 도구 패널에 확대·축소·"위치로 되돌리기" 버튼이 있다.
2. **영역(배경)** — 9개 타원, 각 `REGIONS` 항목의 `cx/cy/rx/ry`(참고 레퍼런스의 GEO 좌표 그대로) + 우리 색 팔레트의 옅은 워시(12~20% opacity) + 점선 테두리. 해당 영역에 발견된 단어가 1개라도 있으면 워시가 살짝 진해지고 라벨이 더 또렷해진다.
3. **엣지(관계)** — `EDGE_PAIRS` 203개. 양쪽 다 발견 → 실선, 한쪽이라도 tier≥1(닿을 수 있는 상태) → 점선, 둘 다 tier 0 → 렌더링하지 않음(잡음 제거).
4. **노드(단어)** — `WORD_ROWS` 145개, 영역 안에서 골든 앵글 스파이럴로 자동 배치(겹치지 않게). **3단계 발견 상태**:
   - **tier 0 (숨김)**: 흐린 점, 상호작용 불가(`pointer-events:none`).
   - **tier 1 (이웃/미확인)**: 점선 원, 라벨은 호버해야 보임. 이미 발견한 단어의 그래프 이웃일 때만 이 상태가 된다.
   - **tier 2 (발견)**: 영역색으로 채워짐, 라벨 항상 노출.
   - **클릭**: tier 1 노드를 클릭하면 발견 처리(tier 2로 전환 + 연결 엣지 실선화)와 동시에 우측 상세 패널이 열린다.

### 3.2 상세 패널 — 우측 고정 사이드바 (v4: 팝업 → 패널)
지도를 가리지 않도록 화면 우측에 고정된 패널로 바뀌었다. 담는 내용:
1. 헤더: 영역명 + 단어명(Pretendard Bold) + 품사 + 닫기 버튼
2. **감정 캐릭터**: 단어의 영역색으로 물든 캐릭터 일러스트 + 소품(`prop`: book/letter/map은 작은 카드, flower는 꽃 점 셋, none은 아무것도 없음) + 그 단어만의 장면 묘사 텍스트
3. 의미(`def`) · **감정 강도**(1~5 바 게이지 + 라벨)
4. **가까운 감정** (그래프 직접 이웃, 최대 4개, 칩 클릭 시 그 단어로 이동+발견) / **조금 다른 감정** (다른 영역 + 강도차 ≥1인 대조 후보, 점선 칩)
5. **감정의 위치**: 영역의 뿌리 단어(`root`)에서 지금 단어까지, 발견된 그래프만 통과하는 실제 BFS 최단 경로를 화살표로 표시
6. 표현 문장(`say`) + 복사 버튼
7. **마음 기록**: 이 단어에 대한 메모 작성(저장 시 감정 서고에 누적) + 이 단어의 기존 기록 목록
8. **저장/저장 취소** 토글 (감정 서고의 "저장한 단어"에 반영)

### 3.3 상태 저장 (v4 신규)
발견/저장/기록은 `localStorage`(`ewm_store_v1`)에 저장되어 `find.html`·`map.html`·`archive.html` 세 화면이 같은 상태를 공유한다. 서버 없는 프로토타입이므로 브라우저를 바꾸면 초기화된다.

### 3.4 시각 규칙
- 노드 반경·라벨 크기·엣지 두께는 상태와 무관하게 거의 동일 — **채움/테두리, 실선/점선, 라벨 노출 여부**로만 상태를 구분한다(색맹 사용자도 형태로 구분 가능).

## 4. 타이포그래피 · 스페이싱 · 모션 · 접근성

- **서체:** 한글 UI 텍스트는 기본적으로 **전부 Pretendard**를 쓴다 — `.font-serif-kr`/`.topbar-brand`는 `font-weight:700`의 Pretendard로 위계를 준다. **IBM Plex Mono는 한글이 아닌 좌표·청구기호(`SAD·07`, `37.5°S` 등 라틴/숫자 라벨)에만 한정**해서 쓴다.
  **예외(v4.1):** 홈(`find.html`)의 히어로 헤드라인·오늘의 단어·영역 이름처럼 "한 순간의 우아함"이 필요한 딱 몇 곳에는 `.font-display-serif`(Noto Serif KR)를 의도적으로 쓴다. 이 예외는 홈 화면에 한정하고, 지도·서고 등 나머지 화면에는 확대 적용하지 않는다.
- 라운딩: `sm 10px · md 20px · lg 28px · pill 999px` — 동일.
- 그림자: 다크에서 쓰던 블랙 글로우 대신 **따뜻한 갈색 계열 소프트 섀도**(`0 8px 20px -8px rgba(38,36,32,.14)`) — 책상 위에 놓인 종이 느낌.
- 모션: 200–260ms ease-out 페이드업 동일. 발견 노드는 `pulse-glow` 3s. `prefers-reduced-motion`에서 정지.
- 접근성: `text-primary(#262420)` on `bg-base(#E8E6D2)` ≈ 12:1 (AAA). 포커스 링 `outline:2px solid #8F5A12`. 터치 타깃 44px 이상. 노드 상태는 색+형태(채움/테두리, 실선/점선) 이중 인코딩.
